# Счётчик просмотров статей

Ghost остаётся источником контента. Счётчик не подключается к MySQL Ghost или ParaPlanet.
Python 3.12 + SQLite из стандартной библиотеки, nginx перед loopback HTTP-сервером.
Публичный endpoint: `https://cms.getmasterok.ru/article-views/{slug}/`.

## Что считается

Клиент делает GET для цифры, затем POST после двух секунд непрерывной видимости вкладки.
SSR, Next prefetch и GET никогда не увеличивают цифру. Один идентификатор статьи в браузере
может добавить просмотр раз в 30 минут; проверка и увеличение атомарны в SQLite.
Идентификатор отдельный для каждой статьи, обновляется после суток неактивности. При
запрете localStorage или Do Not Track клиент только читает число. На сервере остаются
только HMAC-хеши, не исходные IP/ID. Временные записи чистятся раз в пять минут и при POST.
Нельзя интерпретировать цифру как уникальных людей или дочитывания.

Источник разрешённых slug: публичный blog sitemap основного сайта `/sitemap/4.xml`, обновляется
раз в пять минут. При неудаче сохраняется последний список не более суток; при холодном
старте без sitemap endpoint недоступен. Неизвестные slug не создают записи.
Ghost sitemap не подходит: исключает статьи с canonical на основном сайте. Если меняется
номер blog-чанка в sitemap сайта, обновить URL в Catalog.refresh и проверить новые статьи.
**Переименование slug требует отдельного переноса счётчика**; автоматическое слияние по
заголовкам намеренно не делается. Новые статьи начинают с нуля, история не выдумывается.

## Защита и границы

Origin allowlist — защита браузерного вызова, **не аутентификация**: бот может подделать
заголовок. Дополнительно nginx ограничивает запросы по реальному IP (30/мин, burst 12),
служба — новые просмотры по HMAC IP (60/час). X-Real-IP nginx перезаписывает, а не доверяет
пользовательскому X-Forwarded-For. Это базовая защита, не гарантия от распределённой накрутки.
Общие NAT/VPN могут недосчитываться. Сброс хранилища/другой браузер выглядит новым посетителем.
UA известных ботов не учитываются. Тело до 256 байт, только JSON и UUIDv4; SQL параметризован.
Не передаются cookies, query parameters, referrer, имена, email, содержимое статьи или расчётов.

Служба запускается от masterok-views, пишет только /var/lib/masterok-views, ограничена
128 МБ и 20% CPU. Сайт не ждёт счётчик для рендеринга; при недоступности цифра не рисуется.
CSP сайта разрешает только нужный путь CMS. Служба не пишет access-log; общий error-log
nginx может содержать технические сведения об отклонённых запросах согласно настройкам хоста.

## Установка и проверки

Скопировать этот каталог в отдельный staging-каталог сервера 5.129.248.119, выполнить
`sh install.sh` от root **только после согласования установки службы и nginx-маршрута**.
Скрипт сначала запускает тесты, сохраняет исходный CMS-vhost в
`/var/backups/masterok-views/cms.getmasterok.ru.before-counter`, проверяет `nginx -t`, затем
делает reload nginx (без перезапуска Ghost/ParaPlanet). Переменные сайта и API-ключи не нужны.
Код root-owned; системный пользователь не может менять серверную программу.

Проверки: `python3 -m unittest -v test_server.py`, `npm test -- tests/article-views.test.ts`,
GET неизвестного slug → 404, GET известного → число, POST с чужим Origin → 403,
OPTIONS с Origin сайта → точный CORS origin. Нагрузочные/пишущие тесты проводят на временной
базе, не на цифрах опубликованных статей. После перезапуска повторить GET и health служб.

Данные: `/var/lib/masterok-views/views.sqlite3` + WAL/SHM и локальный HMAC-ключ `hash-key`.
Не копировать работающий SQLite через обычный cp. Daily timer использует SQLite backup API;
хранятся последние семь копий в `/var/lib/masterok-views/backups`, только агрегаты без хешей.
Копии **на том же диске** защищают от ошибки базы, не от потери сервера; внехостовый backup —
отдельный инфраструктурный шаг. Ключ нельзя печатать или коммитить.

Откат: удалить только include `/etc/nginx/snippets/masterok-views.conf` из CMS-vhost,
проверить `nginx -t`, reload nginx, остановить/отключить masterok-views.service и backup.timer.
Не восстанавливать старый vhost поверх более поздних посторонних правок. Базу и резервные
копии оставить для восстановления. Вернуть отдельный git commit UI при необходимости.
