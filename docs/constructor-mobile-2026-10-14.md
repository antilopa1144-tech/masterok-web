# Мобильный редактор: жесты и рабочее пространство

База сравнения: `3201c3da`. Область изменений — 3D-взаимодействие и мобильная компоновка. Расчётные формулы, геометрия проекта, упаковки и сохранённые данные не менялись.

## Поведение

- Во время вращения, масштабирования и переноса предмета компактный экран использует DPR не выше 1.35. Через 180 мс после окончания жеста возвращается прежний бюджет (обычно DPR 2). Повторные жесты продлевают период движения. Экспорт принудительно восстанавливает полную детализацию; таймер удаляется при размонтировании. На обычном desktop разрешение не снижается.
- Выбор поверхности разрешён только после одиночного нажатия. Два пальца, отменённое касание и движение с возвратом в исходную точку не выбирают стену или предмет. На исходной сборке ложный выбор после pinch воспроизведён в браузере на 320/390/1440 px.
- Подсказка первого запуска занимает одну строку на телефоне: сцене добавлено 36 CSS px по высоте. Управление камерой — блок 2×2 с кнопками 44×44 px; увеличены кнопки видов и закрытия панели. На ширине до 380 px вкладки видов оставлены текстовыми, чтобы все четыре помещались.

## Проверки

- TypeScript 7: без ошибок; production build: успешно.
- Полный Vitest: 4 137 тестов, 315 файлов; lint: 0 предупреждений.
- Пять E2E создания отдельного проекта и повторной загрузки тёмной темы: успешно, React #418 не воспроизведён.
- Chromium: 320 px (тёмная тема), 390 px и desktop 1440 px. Вращение, pinch со стационарным последним пальцем, возврат разрешения, длинное название, панель материалов, PNG 1600×1400. На мобильных ширинах проверено отсутствие переполнения подписей подсказки и обрезания вкладок.
- Сенсорный выбор стиральной машины → перенос пальцем → завершение → экспорт проекта → отмена → повтор → перезагрузка. Состояние комнаты сверено по экспортируемому JSON; положение сохраняется.

## Нагрузка: пределы измерения

Chromium использовал программный GPU SwiftShader, эмуляцию 390×844 / DPR 3 и замедление CPU 4×. Для обеих сборок выполнен одинаковый путь из 90 перемещений указателя в стандартной комнате и ванной. Это одиночное сравнительное измерение, не гарантия FPS на телефонах.

| Сцена | p95 интервала кадров до | После | Максимальная длинная задача до / после |
|---|---:|---:|---:|
| Комната | 83.3 мс | 50.0 мс | 150 / 120 мс |
| Ванная | 100.0 мс | 50.1 мс | 147 / 120 мс |

На 390 px рабочий буфер новой сцены: 780×1180 в покое, 526×796 в движении, затем снова 780×1180. В движении рисуется примерно на 54.5% меньше пикселей, чем в покое той же версии. Рендер по-прежнему запускается по событиям, постоянного цикла кадров нет.
