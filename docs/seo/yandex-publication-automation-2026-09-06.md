# Яндекс в автоматизации публикации Ghost → Next

Дата исследования: 6 сентября 2026. Статус: **техническая схема, не внедрена**.

Этот документ дополняет [общую схему Ghost → Next → Google](./article-publication-automation-2026-09-06.md): Яндекс.Вебмастер нужен для принятия переобхода и наблюдения, а не как обещание индексации или попадания в рекомендации.

## Подтверждённые возможности

1. API Вебмастера (официально доступна v4.1) работает от OAuth 2.0 и сайта, на который у владельца токена подтверждены права. Для нового приложения Яндекс предписывает scopes `webmaster:hostinfo` и `webmaster:verify`; токен действует шесть месяцев. [Авторизация](https://yandex.ru/dev/webmaster/doc/ru/tasks/how-to-get-oauth), [API Вебмастера](https://yandex.ru/dev/webmaster/).
2. После публикации можно отправить canonical URL на приоритетный переобход: `POST /v4/user/{user-id}/hosts/{host-id}/recrawl/queue`. Ответ `202` содержит `task_id` и фактический остаток дневной квоты `quota_remainder`; не фиксируем лимит числом в коде. [Отправление URL](https://yandex.ru/dev/webmaster/doc/ru/reference/host-recrawl-post).
3. Статус этой заявки читается по `GET .../recrawl/queue/{task-id}`: только `DONE` означает, что робот обошёл URL; `FAILED` требует проверить доступность. `DONE` не является доказательством включения в поиск. [Статус задачи](https://yandex.ru/dev/webmaster/doc/ru/reference/host-recrawl-task-get).
4. Для небольшого набора редакционных URL есть read-only API «Мониторинг важных страниц»: HTTP-статус и дата обхода, `searchable`, причина исключения и `target_url` (redirect/canonical/дубль). Это источник для наблюдения за конкретной статьёй, а не массовая проверка всего сайта. [Важные страницы](https://yandex.ru/dev/webmaster/doc/ru/reference/host-id-important-urls).
5. Sitemap можно один раз зарегистрировать через `POST .../user-added-sitemaps`, а затем наблюдать обычный sitemap через `GET .../sitemaps/{sitemap-id}`: дата загрузки, число URL и ошибок. Уже указанный в `robots.txt` sitemap не надо постоянно добавлять заново: робот регулярно проверяет изменения; в UI ускорение ограничено 10 попытками на хост за 30 дней. [Добавление Sitemap](https://www.yandex.ru/dev/webmaster/doc/ru/reference/host-user-added-sitemaps-post), [статус Sitemap](https://yandex.ru/dev/webmaster/doc/ru/reference/host-sitemaps-sitemap-id-get), [поведение Sitemap](https://yandex.ru/support/webmaster/ru/indexing-options/sitemap).

## Минимальное включение в очередь публикации

После того как проектируемая очередь подтвердит публичный canonical URL (200, canonical/robots, RSS и `/sitemap/4.xml`), отправить IndexNow. Для ограниченного набора приоритетных статей с задержкой обхода предусмотрена отдельная идемпотентная задача `yandex_recrawl` по ключу `ghost_id + revision + canonical`. Не расходовать оба механизма повторно на каждую редакцию без необходимости:

```text
public_ready → POST recrawl → сохранить task_id + quota_remainder
             → poll task_id c backoff до DONE/FAILED
             → через отложенный контроль GET important-urls
             → сохранить crawl/searchable/exclusion/target_url
```

Не расходовать переобход на draft, preview, URL с `noindex`, теговые страницы и повтор той же редакции. При `429` учитывать возвращённый `exceeded_until`; при нулевой квоте отложить до её восстановления. `409 URL_ALREADY_ADDED` сопоставить с уже известной задачей, а не повторять POST. При `401/403` — статус «доступ/права требуют действия», без цикла повторов. Для массовых изменений основой остаются корректный sitemap, ссылки и обход по счётчику Метрики; ручной/очередной переобход имеет дневной лимит. Яндекс указывает обычный ориентир индексации 3–7 дней, это не SLA. [Новые и изменённые страницы](https://yandex.ru/support/webmaster/ru/robot-workings/new-changed), [Переобход](https://yandex.ru/support/webmaster/ru/robot-workings/site-reindex).

### IndexNow

06.09, реализация B: `ops/publication-worker/` проверяет реальную редакцию HTML и RSS, изображения, canonical/robots, sitemap и ссылки; затем отправляет отдельный URL. Автоматический postbuild-пинг убран, старый скрипт оставлен ручным. VPS active после проверки двух настоящих статей, детали в [приёмке B](evidence-2026-09-06-publication-worker.md). Read-only/API-переобход Вебмастера этим worker ещё не подключён.

Ручной `scripts/ping-indexnow.js` не является подтверждением, что Ghost-статья уже доступна на production. Очередь отправляет новый/изменённый/удалённый canonical только после `public_ready` и хранит HTTP-результат принятия. Яндекс поддерживает протокол, но прямо говорит: передача URL **не гарантирует индексацию**. Не слать весь sitemap при каждом событии. [Поддержка IndexNow](https://www.yandex.ru/support/webmaster/ru/indexing-options/index-now).

## Одноразовая настройка доступа

1. Владелец добавляет `https://getmasterok.ru` в Вебмастер и подтверждает права; без этого API возвращает `HOST_NOT_VERIFIED`.
2. Владелец создаёт отдельное OAuth-приложение с двумя указанными scopes и выдаёт токен техническому владельцу сервиса по официальному flow. Токен и client secret — только в секретном хранилище среды очереди, не в Git, чатах, URL и логах.
3. Служба один раз вызывает `GET /v4/user`, затем `GET /v4/user/{user-id}/hosts`, сохраняет только `user_id` и выбранный `host_id`; оба перепроверяются при каждом обновлении токена.
4. Служба читает список sitemap, если корневой sitemap уже найден через `robots.txt`; `POST user-added-sitemaps` нужен только при его отсутствии. Хранить `sitemap_id` и периодически читать фактические ошибки/дату обхода.
5. Владелец добавляет ограниченный набор приоритетных статей в «Мониторинг важных страниц» в интерфейсе. API документирован как чтение выбранных страниц; не выдаём его за API массового добавления URL.

## Что не следует обещать

| Тезис | Статус | Корректная формулировка |
|---|---|---|
| `202` / IndexNow accepted = статья в индексе | неверно | это принятое уведомление или заявка; наблюдаем обход и `searchable` |
| Ghost publish = немедленная выдача Яндекса | неверно | публикация запускает нашу техническую доставку; решение поисковой базы вне контроля |
| «Рекомендации Яндекса» можно включить тем же API | неверно | в Вебмастере это советы по оптимизации поиска, не API ленты |
| Дзен публикуется Ghost webhook-ом | неверно | Дзен — отдельная редакционная площадка/аккаунт и его публикация требует отдельного согласованного контура |
| Рекомендательные переходы измеримы | требует live-проверки | Метрика различает, в том числе, Дзен и другие рекомендательные системы по referrer/UTM; после выпуска сверять отчёт, не приписывать показы без данных |

Термины нельзя смешивать: органический Яндекс.Поиск и статусы Вебмастера — один контур; рекомендации — измеряемый реферальный источник, но не гарантируемая поверхность; Дзен — отдельный канал публикации. [Рекомендации Вебмастера](https://yandex.ru/support/webmaster/ru/diagnosis/recommendations), [отчёт Метрики о рекомендательных системах](https://yandex.ru/support/metrica/ru/sources/recommend-system).

## Приёмка и границы

Дополнительная поверхность: «Видимость сайта в Алисе AI» в Вебмастере показывает упоминания сайта в ответах Алисы по доступной выборке запросов. Это не лента рекомендаций и не полноценный журнал всех показов; проверить наличие отчёта у getmasterok.ru отдельно, не приписывать его данные обычным поисковым кликам. Серверный API этого отчёта в данном исследовании не подтверждён. [Документация отчёта](https://yandex.ru/support/webmaster/ru/service/alice-answers).

- Тестовая публикация создаёт одну задачу, переживает перезапуск, не дублирует revision и не раскрывает токен в логе.
- Сохранены `task_id`, остаток квоты, состояние `IN_PROGRESS/DONE/FAILED` и последующая запись important-pages; эти факты отделены от даты первого наблюдения `searchable=true`.
- Sitemap проверен отдельно по `errors_count`, `urls_count`, `last_access_date`; IndexNow и recrawl не заменяют его.
- Через 7/14/28 дней сравнить Яндекс.Вебмастер и Метрику на сопоставимых окнах. Отсутствующие права, API-ошибка, отсутствие данных и подтверждённый ноль — разные состояния.

Реализация не создаётся этим исследованием; существующие Ghost, Next, IndexNow, Вебмастер и Дзен не изменялись.
