## Решение для следующего пакета

1. **Не создавать дублирующий URL «ламинат со схемой».** В текущем коде title/H1 существующей страницы уже содержат «онлайн со схемой»; description описывает 1/3, 1/2 и ёлочку. Запросы уже ведут на этот URL. Это source evidence, не проверка фактического сниппета Google.
2. **Проверить группу «программа / калькулятор со схемой».** У нескольких строк есть показы на позициях 3–7 и мало кликов. Это кандидаты для более длинного среза и проверки SERP, а не доказанный дефект сниппета: выборки малы, разбивки по устройствам пока нет.
3. **Развести расчёт упаковок и раскладку.** Снять тот же query-срез для `/kalkulyatory/poly/laminat/` и проверить пересечение общих запросов. Одной таблицы раскладки недостаточно для вывода о каннибализации.
4. **Проверить существующий переход, а не строить его повторно.** `LaminateLayoutGenerator.tsx` уже использует `buildLaminateCalculatorHref` и `trackToolRelatedClick`; конфиг связывает инструмент с ламинатом и стяжкой. Нужен реальный desktop/mobile-проход и проверка передачи площади/запаса/закупки и событий, прежде чем называть связь отсутствующей или корректной.
5. **Проверить практические FAQ по источникам и фактическому результату.** В конфиге есть категоричные диапазоны отхода, смещение стыков и зазор. Не менять их без строительной проверки; это отдельный вопрос качества содержания, не вывод из CTR.

Не закрыты: равные окна Яндекс query–URL, Wordstat с операторами/регионом, поведение Метрики/GA4 и чистые конверсии, актуальная выдача, проверка соседнего калькулятора и реального пути. Новые title, статьи и массовые посадочные в этой подготовке не публиковались. Следующая волна плитки остаётся в roadmap; этот срез не является сравнительным ранжированием двух кластеров.
