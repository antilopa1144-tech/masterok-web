# Google и Яндекс: первые рабочие проверки мониторинга

6 сентября 2026, первый Google-отчёт: `2026-09-06T02:00:53Z`, Яндекс: `2026-09-06T02:16:15Z`. Пакет C выполнен **частично**: ежедневные Google/Яндекс-мониторы установлены и активированы; внешние оповещения и расширенный поисковый анализ ещё открыты. Публичный сайт, Ghost, очередь B и счётчик не изменялись этим серверным пакетом.

## Подключено и проверено

- В Google Cloud проекта Masterok создан отдельный `masterok-search-monitor`, без Cloud IAM roles. Search Console API включён после согласования условий владельцем.
- В URL-prefix property `https://getmasterok.ru/` подтверждена роль Restricted. Реальные URL Inspection и Search Analytics с единственным scope `webmasters.readonly` отработали успешно: более широкие права не понадобились.
- Рабочий RSA-ключ создан на VPS; Google получил только публичный X.509 сертификат. Первоначальный неиспользуемый Google-generated key был удалён с отдельного согласия владельца. Приватный рабочий ключ не скачивался с VPS. Срок сертификата — 06.09.2027.
- `ops/search-monitor` установлен в отдельный root-owned каталог/venv под пользователем `masterok-search`. Проверены права: каталог ключа 0750, ключ root:masterok-search 0640, состояние 0700. Для venv установлен официальный Ubuntu `python3.12-venv` и его точечные Python-зависимости; массового обновления ОС/перезапуска Ghost не было.
- Ручной проход завершён успешно. Health `ok`. Ежедневный systemd timer включён: 06:20 UTC + jitter до 5 минут; первый следующий запуск при включении — 06.09 06:22:05 UTC. Существующие publication timers, счётчик и webhook активны.
- 23 offline unit tests обоих мониторов прошли (Google 15, Яндекс 8), включая main, ошибки авторизации, no_rows, partial, corrupt state, failed snapshot и отсутствие статуса индексации. Реальный ручной прогон использовал `google-auth[requests] 2.57.1`. Проверки добавлены в CI; отдельно повторно прошли 37 тестов очереди B.

## Что сообщил Google — не прогноз

Проверены все 24 текущие статьи из публичной карты блога. 16 имеют `verdict=PASS` («отправлена и проиндексирована»), 5 — «просканирована, но пока не проиндексирована», 3 — «URL неизвестен Google» без времени обхода:

- `/blog/otkuda-nachinat-raskladku-plitki/`;
- `/blog/raskladka-laminata-na-tret-ili-polovinu/`;
- `/blog/raskladka-plitki-na-kuhonnom-fartuke/`.

Search Analytics за 27.08–02.09 по календарю America/Los_Angeles: `web` вернул 80 строк date/page для `/blog/`, суммарно 12 кликов и 2036 показов. Фильтр включает индекс блога, не только статьи. `discover` вернул `no_rows`, а не ошибку. Это не доказательство абсолютного отсутствия всех показов Discover и не измерение эффекта сегодняшних изменений; период предшествует релизу. Полный локальный снимок — `output/google-monitor-first-report.json`, не включён в Git.

## Яндекс и оставшаяся граница

Создано OAuth-приложение «Мастерок — мониторинг поиска». Владелец отдельно согласовал `webmaster:hostinfo` и `webmaster:verify`: последний объединяет чтение индексации с правом добавлять сайты; чистого read-only scope для нужного отчёта в форме нет. В дальнейшем код должен использовать только GET к Вебмастеру, не добавлять/удалять сайты и не отправлять URL на переобход.

Экспорт с выводом результата был остановлен защитой инструмента; экспорт без вывода не поддерживался браузером. После дополнительного разрешения владельца использован безопасный отдельный путь: одноразовая loopback-форма → SSH stdin → файл на VPS root:masterok-search 0640. Токен не печатался, не попадал в локальный файл/Git; форма прекратила слушать после успешного импорта, страница с токеном закрыта переходом к настройкам приложения. Создание файла и его права подтверждены. Срок токена — 180 дней, потребуется контролируемая ротация.

Первый реальный GET-проход Вебмастера успешен. Summary: ИКС 10, 149 страниц в поиске, 46 исключённых, `site_problems={}`. Samples: 184 URL, локальный лимит не достигнут; среди них индекс блога и все 24 статьи, включая три свежие, пока неизвестные Google. Различие 149 в summary и 184 в samples не исправлялось и не усреднялось: это разные API-представления с возможной разницей времени обновления. Отсутствие URL в samples не означало бы доказанного отсутствия индексации. Источник — `output/yandex-monitor-first-report.json`, не включён в Git.

После итоговой доработки повторный проход service и health успешны; включён отдельный `masterok-yandex-monitor.timer`, ежедневно 06:35 UTC + jitter до 5 минут. Оба timer подтверждены через `systemctl list-timers`. При сроке токена менее 30 дней health станет неуспешным; внешний канал доставки этого сигнала владельцу ещё не подключён.

Открыты: внешний канал оповещений; поисковые запросы/клики Яндекса и детальная история URL; off-host backup; контролируемая ротация ключей; первая реальная редакционная публикация через B с подтверждённым IndexNow `done`; только затем отключение прежнего rebuild-webhook. Техническая автоматизация не гарантирует рекомендации и не заменяет редакционную работу/кластеризацию.
