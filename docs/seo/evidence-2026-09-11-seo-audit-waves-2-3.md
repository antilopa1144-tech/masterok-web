Ранее сборка проходила за счёт тёплого `.next/cache`; после его очистки это воспроизводится. Для локальной проверки страниц без Ghost используется `next dev`.

## Найденные дефекты, не связанные с мета

**Ответы FAQ на страницах категорий отсутствовали в HTML.** Аккордеон был клиентским (`useState`), ответ попадал в DOM только после клика, при этом `FAQPage`-разметка ответы описывала. Живая проверка `/kalkulyatory/krovlya/` до правки: вопрос в DOM есть, ответа нет. Исправлено переводом на серверные `<details>`.

**Единица измерения в блоке «Потребность и покупка».** `buy_plan.unit` описывает упаковку, а `purchase_quantity` выражен в единицах материала. Клей показывал «125 мешков» вместо 125 кг, арматура — «1 790,1 прутков» вместо погонных метров, шпаклёвка — «60 kg». Исправлено выбором единицы материала, у которого совпадают число и размер упаковки. Расчёты, запас и округление не менялись.

**«Рекомендуем 0 отрезков»** в вентиляции при незаданной длине трассы. Блок покупки теперь не рендерится при нуле.

## Доставка

Все правки в `main`, CI зелёный на каждом коммите: `92a696f`, `a15d558`, `10f9d7b`, `c08ceab`, `d185b00`, `d4a7e2a`, `fdba1c9`, `d0529f9`, `766de22`, `b28f8b3`, `170332f`. Тесты 3431 → 3472.

Проверка живых URL вынесена в одну команду: `npm run verify:live`. Она проверяет семь правил — robots для AI-краулеров, покрытие `llms.txt`, дубль бренда в title, ответы FAQ в HTML категорий, вопросные h2 на калькуляторах, новые блоки усиленных страниц и лимиты title/description по всем URL sitemap. Из HTML перед поиском маркера вырезаются `script` и `style`, иначе JSON-LD выдаёт себя за видимый текст.

Прогон `npm run verify:live` 11 сентября 2026: 7 из 7 проверок падают, 64 расхождения по 148 URL. Это ожидаемо и означает ровно одно — прод отдаёт старую сборку.

Production отдаёт сборку от 15:45. Проверка живых маркеров: `/ai/` возвращает «Что такое Мастерок — справка о сайте — Мастерок» (дубль бренда), `llms.txt` — «65+» без блока «Частые вопросы», ответы FAQ на категориях не в DOM, `robots.txt` без новых AI-краулеров. Вебхук Timeweb принял все push-события (HTTP 201 по данным GitHub), то есть доставка события работает, а сборка не выпускается. Со стороны репозитория препятствий нет: `origin/main` совпадает с локальным, других веток деплоя и deploy-конфигов в репозитории нет.

Следующий шаг: проверить лог сборки приложения в панели Timeweb Cloud Apps. После выпуска свежей сборки — `npm run verify:live` должен вернуть 0 и напечатать «Все проверки пройдены».
