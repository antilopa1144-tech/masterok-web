# Приёмка A: обновление блога без пересборки

6 сентября 2026. **Релиз `6d43fec` выпущен в main и на production.** Изолированный lifecycle, CI и публичные HTTP-проверки прошли. Подключение worker остаётся отдельным этапом; локальный тест не доказывает задержку через CDN или состояние поискового индекса.

## Что сделано

Вместо вечного `_postsCache` используется `unstable_cache` Next.js 15 с тегом `ghost-blog` и TTL 60 секунд. Статья и каталог читают одну опубликованную выборку Ghost. Новые статьи/теги работают в `force-dynamic`; исчезнувшие — HTTP 404. Общий `loading.tsx`, раньше отправлявший 200 до проверки адреса, перенесён в раздел инструментов. Блог ожидает проверку адреса без общего skeleton; отдельный loading калькуляторов сохранён.

RSS, карты и связанные поверхности получили короткую политику обновления. Корневой sitemap больше не объявляет одинаковый выдуманный lastmod всех частей. У статей сохраняются полные даты CMS, включая правки в тот же день; локальные content overrides не затирают более позднюю правку Ghost. Крупные превью разрешены в robots metadata. Формулы, контент статей и счётчик просмотров не менялись.

## Закрытый контракт для B

`POST /api/blog/revalidate` — внутренний вызов worker, не публичный Ghost webhook. Заголовок `Authorization: Bearer …`, секрет `BLOG_REVALIDATE_SECRET` длиной минимум 32 символа в секретном хранилище обеих служб. Без конфигурации — 503, неверная авторизация — 401. Не передавать секрет в URL, Git или чат.

JSON: `event` (`published`, `edited`, `unpublished`, `deleted`), `postId`, `revision`, `slug`, необязательный `previousSlug`. До 8 KiB по фактическим байтам; неизвестные поля и невалидные slug отклоняются. Ни URL загрузки, ни пути, ни теги кеша отправитель не задаёт. Обновляется только фиксированный список blog-зависимостей. Ответ `{accepted:true, publicReady:false}` не означает успешную публикацию: worker отдельно проверяет публичные URL. Повторы безопасны; постоянная очередь и дедупликация относятся к B.
