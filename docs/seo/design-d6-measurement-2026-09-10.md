# D6: технический протокол измеримости

Только определения из исходников и план проверки. Закрытые показатели, выгрузки, идентификаторы ресурса и результаты чтения кабинетов сюда не включаются. Локальные аналитические материалы хранятся в игнорируемой `.local-analytics/`; не использовать для них `git add -f`.

## Контракт событий

- `useCalculator.ts`: start ограничен ref один раз за экземпляр hook; calculate отправляется после явного запуска расчёта и может повторяться. Отношение количества событий calculate/start не является конверсией.
- `CalculatorWithMikhalych.tsx`: result_view ограничен ref; использует IntersectionObserver с fallback. Это условие видимости, не синоним calculate.
- `SaveToProjectButton.tsx`: save отправляется после await сохранения. Исторический calculator=calcId сохранён; добавлен calculator_slug для связи с calculator у start/calculate. Для старых событий нужна таблица соответствия; новые данные появятся только после выкладки. Старые вызовы из инструментов без slug сохраняют прежний контракт.
- `ProjectEstimateView.tsx`: print отправляется перед window.print, CSV перед созданием/скачиванием файла, clipboard после успешной записи. Print не доказывает физическую печать; CSV не доказывает сохранение файла пользователем.
- `analytics.ts`: отправка зависит от наличия ym/gtag, ошибки подавляются; `runtime.ts` разрешает production-домены. Вызов в коде не доказывает приём события сервисом.

## Следующий ограниченный пакет

1. Проверить отправку и приём project_export в контролируемом сценарии; не добавлять второй счётчик поверх существующего.
2. После выкладки проверить calculator_slug в сохранении; для новых событий сопоставлять его с calculator у start/calculate. При необходимости отдельно зарегистрировать параметр в интерфейсе аналитики — регистрация не выполнена кодом сайта и не восстанавливает старые данные.
3. Проверить даты внедрения событий, часовой пояс и исключение тестовых визитов; сравнивать полные сопоставимые периоды, отдельно устройства и источники.
4. Хранить точные показатели и результаты кабинетных проверок только локально. В Git фиксировать технические изменения и методику без закрытой аналитики.

Измерительная часть D6 остаётся открытой. Технические тесты не подтверждают рост конверсии, SEO или Discover.

## Проверки дополнения calculator_slug

Regression сначала подтвердил отсутствие slug, затем прошёл для ym и gtag; старый двухаргументный вызов сохраняет прежние параметры. Lint и полный набор 3327 тестов прошли. На момент этого пакета общий TypeScript-check выявлял ошибки в тестах и копии репозитория в output; последующее исправление описано ниже. Кабинетные результаты проверки хранятся в локальном протоколе; формулы и видимый UI не менялись.

## Следующий технический пакет: строгая проверка типов

Добавлена команда `npm run typecheck` и обязательный шаг в CI. Исправлена типизация тестов без ослабления strict-режима и исключения настоящих тестов. Проверки обязательных сценариев и практических заметок явно падают при их отсутствии. Тесты кровли и лестницы теперь передают professional напрямую, без helper, который заменял режим на basic.

Каталог временных артефактов `output` исключён из TypeScript-проекта: вложенная старая копия репозитория не должна компилироваться как часть приложения. Файлы не удалены. Производственные формулы, UI и canonical-фикстуры этим пакетом не меняются. Локальная проверка типов проходит; успешная проверка кода не означает завершения измерительной части D6.
