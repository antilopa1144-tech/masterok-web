# D6: технический протокол измеримости

Только определения из исходников и план проверки. Закрытые показатели, выгрузки, идентификаторы ресурса и результаты чтения кабинетов сюда не включаются. Локальные аналитические материалы хранятся в игнорируемой `.local-analytics/`; не использовать для них `git add -f`.

## Контракт событий

- `useCalculator.ts`: start ограничен ref один раз за экземпляр hook; calculate отправляется после явного запуска расчёта и может повторяться. Отношение количества событий calculate/start не является конверсией.
- `CalculatorWithMikhalych.tsx`: result_view ограничен ref; использует IntersectionObserver с fallback. Это условие видимости, не синоним calculate.
- `SaveToProjectButton.tsx`: save отправляется после await сохранения. Параметр calculator здесь calcId, а у start/calculate — slug. Для сопоставления нужна таблица соответствия.
- `ProjectEstimateView.tsx`: print отправляется перед window.print, CSV перед созданием/скачиванием файла, clipboard после успешной записи. Print не доказывает физическую печать; CSV не доказывает сохранение файла пользователем.
- `analytics.ts`: отправка зависит от наличия ym/gtag, ошибки подавляются; `runtime.ts` разрешает production-домены. Вызов в коде не доказывает приём события сервисом.

## Следующий ограниченный пакет

1. Проверить отправку и приём project_export в контролируемом сценарии; не добавлять второй счётчик поверх существующего.
2. Сверить calcId/slug перед построением последовательной воронки одного калькулятора в одном сервисе.
3. Проверить даты внедрения событий, часовой пояс и исключение тестовых визитов; сравнивать полные сопоставимые периоды, отдельно устройства и источники.
4. Хранить точные показатели и результаты кабинетных проверок только локально. В Git фиксировать технические изменения и методику без закрытой аналитики.

Измерительная часть D6 остаётся открытой. Технические тесты не подтверждают рост конверсии, SEO или Discover.
