# React: гидратация и предупреждения после обновления

## Изменения

- Устранены 89 диагностик исходного ESLint-прогона. Убрано временное понижение правил React Hooks до warning; `npm run lint` запрещает новые предупреждения.
- Редактор сначала гидратирует одинаковый серверный loading-shell, затем создаёт клиентскую сессию. Начальные параметры читаются из маршрутизатора Next.js один раз: `window.location` может ещё содержать предыдущий адрес при клиентском переходе. Смена URL автосохранением не перезапускает чтение проекта.
- Ref для данных рендера заменены состоянием; ref для внешних обработчиков обновляются после commit. ModalWindow сохраняет фокус при обновлении родителя, Escape использует актуальный callback.
- Настройки из URL и браузерного хранилища инициализируются без цепочек синхронных обновлений в эффектах. Чек-лист и календарь продолжают работать в памяти при запрете localStorage.
- Загрузка кабинета и локальных списков применяет результаты I/O в callbacks; где запрос зависит от открытого компонента, добавлена отмена устаревших ответов.
- `src/middleware.ts` перенесён в `src/proxy.ts` по соглашению Next 16. Сохранены matcher, редиректы, ранние 404 и CSP. Кэш `/_next/static` снова управляется Next.js.
- Исправлена нестабильность теста ISR: Next использует Date и performance при записи/проверке срока тега, поэтому тест управляет обоими часами.
- В первом CI после исправлений прошли все 4 125 тестов и 102 браузерные проверки. Обнаруженные предупреждения устаревшего Node 20 относились к GitHub Actions: checkout, setup-node и upload-artifact обновлены до официальных версий 7.0.1, 7.1.0 и 7.0.2 на Node 24. Версия Node приложения остаётся 24.

Формулы, коэффициенты, упаковки и значения по умолчанию не менялись. В частности, у раскладки листов сохранён запас 5%, а явно переданный `reservePercent=0` остаётся нулём. Незавершённая миграция платёжного провайдера исключена из релизного набора.

## React #418: границы вывода

В исторических данных был #418 с `args[]=HTML` при входе в редактор. Точного различия серверного и клиентского HTML эти записи не содержат. На опубликованной версии Next 16.4.0 / React 19.3.0 ошибка не повторилась в шести чистых сессиях, включая задержку загрузки JS.

[React issue #37321](https://github.com/react/react/issues/37321) описывает похожую гонку потокового HTML и прогретого JS-кэша; это гипотеза, а не подтверждённая причина ошибки Мастерка. Патчи scheduler, отключение SSR и подавление ошибок гидратации не добавлялись.

Новые регрессии проверяют SSR → hydrateRoot, StrictMode, сохранённый проект, мастер нового проекта, pending router URL, сохранённые тёмные темы. `e2e/constructor-hydration.spec.ts` проверяет создание/сохранение и reload с прогретым кэшем при 1500 kbps / 20 ms на 1440 и 390 px; перехватывает pageerror и сообщения о гидратации. Он включён в CI smoke-набор.

## Локальная проверка

Проверялся чистый снимок HEAD + файлов задачи, без чужих изменений commerce и сгенерированных parity fixtures:

- 4 125 тестов, 312 файлов — пройдены.
- ESLint — 0 ошибок и предупреждений; TypeScript — пройден.
- Production webpack build — пройден, предупреждения middleware/Edge/cache служебных чанков устранены.
- Девять затронутых страниц на 390 px в тёмной теме: HTTP 200, нет pageerror/#418 и горизонтального переполнения.
- Отдельные UI-регрессии: фокус модалки, выбор поиска с клавиатуры, последний режим точности, запрет localStorage, восстановление календаря, сохранение размеров и гидроизоляции при смене пакета.
- Браузер: два разных проекта через лендинг на 1440/390/320 px, создание комнаты и ванной с последующим warm-cache reload на 1440/390 px — пройдены. Ошибок гидратации и других pageerror нет.
- После переноса proxy проверены 308 для trailing slash, 301 на каноническую категорию, 404 неизвестного калькулятора, CSP статьи и `public, max-age=31536000, immutable` у чанка Next.

Результаты CI, идентификатор публикации и публичные проверки записываются отдельно после push. Локальная эмуляция не заменяет проверку на физических смартфонах.
