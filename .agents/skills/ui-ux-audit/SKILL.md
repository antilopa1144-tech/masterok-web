# UI/UX Parity Audit

## Сравнить один контракт

1. Зафиксировать калькулятор, версии обеих платформ и ожидаемый canonical-контракт.
2. Составить таблицу полей: id, подпись, тип, единица, дефолт, диапазон, обязательность и условие видимости.
3. Пройти одинаковые сценарии на web и mobile: дефолт, альтернативный режим, ошибка, пограничное значение и повторный расчёт.
4. Сравнить структуру результата, точную потребность, итог к покупке, запас, упаковки, остаток и пояснения.

## Классифицировать расхождения

- **Contract:** разные поля, дефолты, единицы или расчётный смысл.
- **Validation:** разные допустимые значения или сообщения.
- **Discoverability:** возможность существует, но скрыта в обычном сценарии.
- **Presentation:** числа совпадают, но объяснение или приоритет результата различаются.
- **Platform-specific:** различие оправдано системным UX и не меняет контракт.

Не объявлять parity по одному совпавшему числу. Для фактической browser-проверки web использовать `$verify-user-flow`; для расчётных расхождений — `$shared-formulas-sync` и `$audit-calculator`.

## Отчитаться

Показать точные различия, каноническое ожидаемое поведение, серьёзность и минимальный план унификации. Не изменять код, если запрос ограничен аудитом.
