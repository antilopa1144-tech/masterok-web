# Матрица релизных проверок

| Тип изменения | Минимум во время работы | Перед commit |
|---|---|---|
| Формула, коэффициент, единица | Regression и точечные unit-тесты, `sync:all`, parity | lint, полный test, parity, diff-check |
| Поле, дефолт, структура результата | Точечные тесты, sync, parity, пользовательский flow | lint, полный test, parity, diff-check |
| UI калькулятора | Точечные тесты, desktop/mobile flow | lint, полный test, E2E по риску, diff-check |
| SEO, metadata, маршрут | Проверка source и render | lint, полный test, build по риску |
| Ghost или server data flow | Regression-тесты ошибок и пустых ответов | lint, полный test, build с корректным окружением |
| Текст без поведения | Проверка страницы и ссылок | lint; полный test по правилам проекта |

## Особые случаи

- `npm run build` запускает генерацию meta и postbuild. Проверять появившийся diff после команды.
- Ghost build без настроенного окружения может падать намеренно: не маскировать ошибку пустым массивом и не печатать секреты.
- Untracked-файл отсутствует на production, даже если локально всё работает.
- Изменённые parity-фикстуры могут принадлежать другой задаче. Сопоставлять их с изменениями canonical-спеков до staging.
- Browser/source/tests являются разными видами evidence; один не заменяет другой.

## Финальный порядок

1. Inspector.
2. Точечные проверки.
3. Генерация и parity, если применимо.
4. Lint и полный test.
5. Build/E2E по риску.
6. `git diff --check`.
7. Точечный staging и просмотр cached diff.
8. Commit, push и CI только в разрешённом объёме.
