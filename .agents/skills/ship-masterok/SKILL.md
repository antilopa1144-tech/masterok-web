# Ship Masterok

## Не расширять разрешение

Проверки выполнять как обычную часть завершения задачи. Commit, push, PR или деплой выполнять только когда пользователь это запросил. Учитывать, что push в `main` может запускать сборку Timeweb.

## Проверить рабочее дерево

1. Выполнить `scripts/inspect-release-state.ps1` из этого skill.
2. Разделить файлы задачи, чужие изменения, generated-файлы и временные артефакты.
3. Не откатывать и не включать в commit чужие изменения.
4. Никогда не печатать содержимое `.env`; при обнаружении env-файла в status остановить публикацию и сообщить риск.

## Выбрать проверки

Прочитать [references/release-matrix.md](references/release-matrix.md) и выполнить проверки по типу изменения. Начинать с точечных тестов. Перед commit выполнять обязательные `npm run lint` и `npm test`, если проектные инструкции не изменились.

Для расчётной логики дополнительно выполнять `npm run sync:all` и `npm run test:parity`. После генерации снова проверять diff: генератор не даёт права перезаписать чужие незакоммиченные фикстуры.

## Подготовить commit

1. Выполнить `git diff --check`.
2. Добавить только явные task-owned paths; не использовать широкое `git add .` в dirty worktree.
3. Проверить `git diff --cached --stat` и `git diff --cached`.
4. Создать один осмысленный commit или несколько только при реальном разделении изменений.
5. После commit повторно выполнить inspector и подтвердить, что нужные файлы действительно tracked.

## Опубликовать

1. Push выполнять в согласованную ветку; для обычного завершённого исправления проекта — в текущий `main`, когда это прямо следует из запроса.
2. Подтвердить, что локальный `HEAD` совпадает с ожидаемым remote commit.
3. Проверить CI, если он доступен. Не считать push завершённым релизом при красном CI.
4. Не называть production проверенным без отдельного live-evidence.

## Отчитаться

Указать commit, ветку, команды и результаты, оставшиеся незакоммиченные файлы, CI и всё, что не удалось проверить.
